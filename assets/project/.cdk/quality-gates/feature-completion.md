# Feature Completion Gate

- [ ] Acceptance criteria are explicit and mapped to implementation.
- [ ] Existing repository patterns were inspected and followed.
- [ ] Scope stayed limited; unrelated changes were avoided.
- [ ] Inputs, permissions and error states are handled.
- [ ] Tests cover success and meaningful edge/failure cases.
- [ ] Relevant tests/checks were actually run.
- [ ] API, database, configuration and docs were updated where needed.
- [ ] Final diff was inspected.
- [ ] Known limitations and unverified areas are disclosed.
