# Database Change Gate

- [ ] Existing schema and migration conventions were inspected.
- [ ] Constraints, indexes and query patterns were considered.
- [ ] Data ownership and tenant boundaries are enforced.
- [ ] Locking, downtime and backfill volume were assessed.
- [ ] Rolling-deploy compatibility was considered.
- [ ] Migration is restartable or recovery is documented where needed.
- [ ] Validation and rollback/forward-fix are defined.
- [ ] Backup/restore readiness is confirmed for risky changes.
- [ ] No production migration ran without explicit approval.
